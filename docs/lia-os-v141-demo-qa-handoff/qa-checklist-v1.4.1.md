# QA Checklist — LÍA O.S. v1.4.1 (Demo & Handoff)

## Objetivo

Asegurar que la demo se vea consistente, estable y alineada con la narrativa ejecutiva antes de cualquier presentación.

## A. Verificación visual (premium experience)

- [ ] La estética dark/cyan se mantiene consistente en todas las pantallas.
- [ ] No hay saltos visuales bruscos entre módulos.
- [ ] Tipografía, espaciado y jerarquía visual se perciben coherentes.
- [ ] Cards, paneles y overlays mantienen acabado glassmorphism uniforme.
- [ ] Contraste suficiente para lectura ejecutiva en contexto de demo.

## B. Flujo funcional de demo

- [ ] Acceso inicial y transición al dashboard sin bloqueos visuales.
- [ ] Navegación entre módulos responde de forma estable.
- [ ] Predictive Intelligence renderiza señales esperadas (mock).
- [ ] Cognitive Space Engine muestra grafo y relaciones esperadas (mock).
- [ ] Dynamic Command Layer permite interacción y confirmación visual.
- [ ] Agenda 24h se visualiza de forma consistente.
- [ ] Módulos de seguimiento, documentos y alertas cargan correctamente.

## C. Integridad narrativa

- [ ] El presentador no comunica capacidades no implementadas.
- [ ] Se verbaliza explícitamente que no hay ejecución real de acciones.
- [ ] Se verbaliza explícitamente que no hay APIs reales conectadas.
- [ ] La demo se posiciona como prototipo funcional premium.

## D. Higiene pre-demo

- [ ] Build del frontend exitoso.
- [ ] Revisión de términos prohibidos completada en docs y frontend.
- [ ] No se incluyeron marcas o nombres restringidos.
- [ ] No hubo cambios en backend/auth/deploy/componentes/estilos.

## E. Criterio de salida

La demo está lista para cliente cuando:

1. Visual premium consistente.
2. Flujo sin errores perceptibles.
3. Mensaje comercial alineado a límites reales.
4. Roadmap siguiente fase claramente explicado.
